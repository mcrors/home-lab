## Standards

### `infra/playbooks/k3s.yaml`
No smells. The new play matches the shape of every surrounding play. Clean.

### `infra/roles/node_labels/tasks/main.yaml`

**Repeated Switches** (judgement call)
The `nuc → x-large` / `potato → small` mapping is encoded inline. If `node_type` drives branching elsewhere (taints, scheduling), this mapping will be duplicated. Consider extracting to a lookup in `vars/main.yaml`.

**Primitive Obsession** (judgement call)
`node_type` is a bare string with no validation. A typo (`Nuc`, `potatoe`) silently produces a wrong label. An `assert` task before the block would catch this.

**Mysterious Name** (minor, judgement call)
The block's `delegate_to: localhost` / `connection: local` is non-obvious — the intent is that `kubectl` runs from the control node, not the target. A `name:` on the block would clarify it.

**Data Clump** (judgement call)
`k3s_node_name` and `node_size` are derived only to feed the two label tasks. If labels grow, this becomes a `set_fact` per label. A single `set_fact` with a `labels` dict + one looping task would scale better.

## Spec

**(a) Missing or partial**

- **Memory threshold is off.** Spec: `medium` = "Pi with ≤4GB RAM", `large` = "Pi with ≥8GB RAM". Implementation uses `≤ 5000 MB` — that's ~4.9 GB, which misclassifies boards in the 4–5 GB range. Threshold should be `<= 4096` (or `<= 4500` with OS-overhead margin).

- **No hook for future `node_type` removal.** Spec: *"coordinate with `workload-affinity-audit.md`"* / *"Do not remove `node_type` until audit is complete."* The role re-applies `node_type` but there is no TODO, tag, or cross-reference to track the eventual removal.

- **New-node bootstrap path unaddressed.** Spec: *"Consider adding label application to the k3s setup role so new nodes get labelled automatically."* Soft requirement, but unaddressed.

**(b) Scope creep**

- **`node_type` is actively overwritten.** The spec only introduces `node_size`; it says nothing about managing `node_type` via Ansible at this stage. Overwriting it risks unintended changes if inventory values diverge from what nodes currently carry.

**(c) Implemented but wrong**

- **`≤ 5000 MB` threshold** (same as (a) above) — on real Pi hardware `ansible_memtotal_mb` reads ~3700–3800 MB for a 4 GB board and ~7700–7900 MB for 8 GB. The 5000 MB cutoff could misclassify a 6 GB board as `medium`. Fix: `<= 4096` or `<= 4500`.
