# M4: delete the local chart and retire the old JENKINS_HOME

## Context

The new deployment is running and has built an image. The old assets can go.

See `docs/jenkins/jenkins-prd.md` section 8 (Decommission).

## Scope

### Delete the local chart

Delete the `jenkins/` directory. It shares no live object with the new release — different namespace, different PV, different PVC name — so deletion touches nothing running.

Confirm first that nothing references it: `git grep -n "jenkins/"` should return only documentation.

### Retire the old home

The export `/export/jenkins` on `lib-hp-01` (`192.168.1.96`) holds Jenkins 2.535, 259 plugins, and an empty `jobs/` directory.

1. Archive it to a tarball and store it wherever the other cold archives live.
2. Remove the NFS export through the OpenMediaVault UI. `/etc/exports` on that host is generated by OMV and warns against hand editing — this is why the ticket is `ready-for-human`.
3. Confirm no cluster object references `192.168.1.96:/jenkins` afterwards.

### Update TODO.md

Remove the "Add jenkins agent" block. All four of its items are closed:

- "Fix reverse proxy issue" — `jenkinsUrl` is set.
- "Add pi, potato and nuc node labels" — was already done by the `node_labels` role.
- "Move jenkins to pi node" — the controller runs on a medium pi.
- "Set executors to 0" — kept from the chart default.

## Notes

- Do not delete the old home before the new install has run a successful build and survived a controller restart.
- Keep the archive until the next Longhorn backup of the new PVC has been verified.
